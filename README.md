# 同传

桌面同声传译，macOS / Windows 通用。打开应用看到的是一条盖在屏幕底部的字幕看板：

- **听**：把电脑里播放的声音（视频、会议软件）实时翻成中文字幕，可选朗读。
- **说**：把你对着麦克风说的中文翻成对方的语言，用语音播出来；输出设备选虚拟声卡，会议里的人就能直接听到。

支持中文和英、日、韩、俄以及德、法、西、葡、意等欧洲语言互译。底层是阿里云百炼的实时同传模型，听和说可以各选各的，见[模型](#模型)。

## 三个窗口

| 窗口     | 用途                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 字幕看板 | 主界面。无边框、透明、置顶，能盖住全屏视频。字幕区铺满窗口，只显示对方的话的译文，按直播字幕的方式滚动：固定显示最新几行（默认 2 行），新字从下面补上，旧行从上面滚走。默认只显示确认过的译文，出现了就不再变。原文和「说」的字幕条默认不显示，可以在工具栏上打开。鼠标移上去才出现工具栏：收听、说话、按住说话、「我 ⇄ 对方」语言、原文、说的字幕、行数、清屏、记录、设置、退出，以及字号、字色、底色和两种透明度。拖动任意空白处移动，拖右下角缩放 |
| 翻译记录 | 和看板同一套外观，颜色和透明度跟看板走。左右两栏，左边听、右边说，每段原文在上、译文在下。可置顶、清空                                                                                                                                                                                                                                                                                                                                               |
| 设置     | 账号、翻译、音色、术语表、外观。主题可选跟随系统、白天、黑夜                                                                                                                                                                                                                                                                                                                                                                                         |

没填 API Key 时启动会自动打开设置，看板上的收听、说话都是禁用的。「清除账号」会停止所有通道，删掉保存的 Key 和复刻音色。

听和说共用一套「我 ⇄ 对方」的语言。设置改动立即生效：换模型、语言、术语表、音色、断句方式时，正在进行的通道会自动断开重连（会漏掉不到一秒的声音）；换麦克风、声音来源、输出设备时直接切过去，不用停。

采集和播放放在一个隐藏的引擎窗口里，界面窗口开开关关都不影响正在进行的通道。

## 准备

- Node.js 20+
- 阿里云百炼 API Key，在设置的「账号」里填，检查通过才保存。

### API Key 存在哪

- Key 保存在本机的用户数据目录（macOS 是 `~/Library/Application Support/live-interpreter/settings.json`），用系统的加密存储保存（macOS 钥匙串 / Windows DPAPI），文件里没有明文。
- 安装包里只有编译后的代码和依赖，**不会带上 Key**；别人装了要填自己的 Key。
- 开发版（`npm run dev`）和打包版共用这个配置目录。在两者之间切换时，macOS 可能弹窗问是否允许访问「live-interpreter Safe Storage」，选「始终允许」即可。

## 退出时会不会还连着服务

不会：

- **正常退出**（看板上的 ×、⌘Q、关掉看板）：先让两条通道发 `session.finish`、把最后一段译完，再断开连接，最多等 2 秒。
- **异常退出**（崩溃、强制结束）：进程没了，系统会关掉它的网络连接，服务端随即断开。
- **电脑睡眠**：先停掉所有通道，醒来后重新开始。
- **音频引擎崩溃**：停掉所有通道、重建引擎，看板上会提示重新开始。

## 系统声音怎么采集

| 平台        | 方式            | 需要做的                                                                   |
| ----------- | --------------- | -------------------------------------------------------------------------- |
| Windows     | WASAPI loopback | 无                                                                         |
| macOS 14.2+ | CoreAudio Tap   | 首次开始收听时，在「系统设置 → 隐私与安全性 → 录屏与系统录音」里允许本应用 |

macOS 上**开发模式下系统声音可能采不到**：`npm run dev` 从终端启动时，系统录音权限算在终端头上，终端的 Info.plist 里没有 `NSAudioCaptureUsageDescription`。要测收听通道，用 `npm run pack:mac` 打出来的 .app；或者在声音来源里选一个虚拟声卡输入（比如 BlackHole）。

## 把译音送进会议软件

| 平台    | 虚拟声卡                                          | 「说」的译音输出 | 会议软件里的麦克风 |
| ------- | ------------------------------------------------- | ---------------- | ------------------ |
| macOS   | [BlackHole](https://existential.audio/blackhole/) | BlackHole 2ch    | BlackHole 2ch      |
| Windows | [VB-CABLE](https://vb-audio.com/Cable/)           | CABLE Input      | CABLE Output       |

### 安装虚拟声卡

macOS：

```bash
brew install blackhole-2ch
```

Windows：在 PowerShell 里下载官方驱动包并解压（`VBCABLE_Driver_Pack45.zip`，官网 2024 年 10 月发布，支持 XP 到 Win11，32/64 位和 ARM64）：

```powershell
Invoke-WebRequest https://download.vb-audio.com/Download_CABLE/VBCABLE_Driver_Pack45.zip -OutFile "$env:TEMP\VBCABLE.zip"
Expand-Archive "$env:TEMP\VBCABLE.zip" "$env:TEMP\VBCABLE" -Force
explorer "$env:TEMP\VBCABLE"
```

在打开的文件夹里，右键和你系统对应的 Setup 程序 →「以管理员身份运行」→ Install Driver，装完重启电脑（官网要求安装、卸载后都重启）。

也可以用 Chocolatey 装，但这是社区维护的包，停在 2019 年的 43.0 版，比官网旧：

```powershell
choco install vb-cable
```

winget 上没有收录 VB-CABLE。

- 译音输出选「系统默认输出」时，译音从你的耳机或扬声器出来，自己会听到。
- 选了虚拟声卡后想在耳机里也听一份，打开「耳机里也听自己的译音」。
- 只想看文字，选「不出声，只出文字」，服务端只回文字，省掉音频的费用。

## 模型

在设置的「翻译」里，听和说各选一个模型，两条通道各连各的。

| 模型                                                   | 默认用在 | 特点                                                                                                                                       |
| ------------------------------------------------------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Qwen3.8 同传（`qwen3.8-livetranslate-flash-realtime`） | 听       | 百炼的同传首推，出字更快。译文按增量推送，只往后追加、不改写；可以按说话人断句。支持热词、按住说话、边说边复刻；不支持固定音色和同语种跳过 |
| Qwen3.5 同传（`qwen3.5-livetranslate-flash-realtime`） | 说       | 支持固定音色，第一句就是你的声音。推送的是「已确认的全文 + 还会被改写的尾巴」                                                              |

- 两个模型在北京地域的单价相同。
- Qwen3.8 的文档写得不全，能力以对真实服务的探测为准（`LIVE_MODE=probe npm run test:live`）。文档外的两处坑已经处理：会话配置必须带 `translation`；不传音色时服务端默认的 `Chelsie` 它自己不支持，所以总是显式传 `Tina`，边说边复刻时传 `default`。
- 固定音色要先用复刻接口生成音色，复刻接口是否支持 Qwen3.8 还没确认，所以「说」默认用 Qwen3.5。
- 百炼出了同一套协议的新模型，可以选「自定义模型 ID」直接填，再选按哪个版本的协议对接。
- 没收录 `qwen3-livetranslate-flash-realtime` 和 Gummy：两者 2026-10-10 下线。

### 听：字幕怎么出

- **稳定优先**（默认）：只显示确认过的译文；前一句还没译完时，后一句先不上字幕，字只会往后追加，不会改字，也不会插到中间。
- 打开「字幕里显示还没确认的译文」：出字更快，但还没确认的部分会被改写，字幕会跳动。Qwen3.5 确认得慢，连续说话时稳定优先要晚 1～2 秒出字；Qwen3.8 推来的都是确认过的字，开不开差别不大。
- 断句可调：停顿多久算一句（默认 1 秒；调长一句更完整，调短出字更快），以及背景音过滤（灵敏 / 标准 / 抗噪）。
- 用 Qwen3.8 时可以打开「按说话人断句」（默认关），换人说话就另起一句。服务端要先认出是谁在说，每次换人会晚 2～3 秒出字；背景音过滤由服务端固定，只能调停顿。
- 这些数字来自 `LIVE_MODE=listen npm run test:live` 的测速，换网络、换地域会有出入，可以自己跑一遍。

## 音色

| 模式       | 效果                                                                                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 预设音色   | 服务端的预设音色                                                                                                                                          |
| 边说边复刻 | 开始说话后服务端边听边复刻。复刻完成前，开头几句会先用默认音色                                                                                            |
| 固定音色   | 在设置里录一段 10~20 秒的朗读，用百炼的声音复刻接口（`qwen-voice-enrollment`）生成专属音色，会话里用 `frequency: never` 加这个音色 ID，第一句就是你的声音 |

复刻音色时指定的模型要和「说」用的模型一致，不一致时自动退回边说边复刻。「说」用的模型不支持复刻时，音色页会提示并改用预设音色。清除账号或删除音色时，会一并删掉服务端的音色。

## 说话方式

- **停顿自动断句**：一直开着麦克风，停顿超过设定时长（默认 0.8 秒）就翻译一句。
- **按住说话**：按住看板上的「按住说话」或空格说话，松开发送（松开后再收 0.4 秒声音才发，免得最后一个字被截掉）；在其他应用里（比如会议软件在前台）按 `⌘⇧Space` / `Ctrl+Shift+Space` 开始，再按一次发送。

外放时，系统声音会把自己的译音录回收听通道。默认开着「播报我的译音时暂停收听」，生效时看板上的收听按钮会显示「暂停中」；戴耳机可以关掉。

## 术语表

两张表，一行一条 `原词 = 译法`，`#` 开头的行不生效，格式不对的行会标出行号并跳过。对应百炼的热词参数 `translation.corpus.phrases`，比如 `提测 = hand off to QA`。

## 测试

```bash
# 纯逻辑：术语表解析、两套协议的会话配置（含三种音色）、事件合并、段落配对、增量拼接、字幕显示规则
npm run test:unit

# 全链路：Chromium 假麦克风 → 引擎 → 主进程 → 本地模拟的百炼服务 → 看板 / 记录 / 设置
# 覆盖没 Key 时的禁用和引导、清除账号、听、说、记录窗口、主题、按住说话、固定音色复刻、
# 换模型、字幕显示方式、断线重连、正常退出和强杀进程；截图在 tests/.output/shots
npm run test:e2e

# 真实百炼联调（会产生少量费用）：推一段中文语音，统计已确认的译文有没有被改写、出字延迟、
# 热词是否生效；Qwen3.8 另外跑按住说话和边说边复刻
DASHSCOPE_API_KEY=sk-xxx npm run test:live

# 「听」的测速：两个人轮流说的英文对话，按看板的显示规则回放，
# 统计每句原文出来后译文多久上屏、稳定优先比显示未确认晚多少、被上一句压住多久
LIVE_MODE=listen DASHSCOPE_API_KEY=sk-xxx npm run test:live

# 只握手不推音频，逐项看 Qwen3.8 收不收文档没写明的参数（不产生费用）
LIVE_MODE=probe DASHSCOPE_API_KEY=sk-xxx npm run test:live
```

- 端到端测试用独立的数据目录和模拟钥匙串，不会读写你日常用的设置，也不会弹钥匙串授权。
- 端到端测试的假麦克风放的是程序生成的「嗡声」，按说话的节奏有声、停顿；模拟服务只按音量断句，不做识别。
- 联调默认在 macOS 上用 `say` 现场合成一段中文；其他系统或想换内容时，用 `LIVE_WAV=录音.wav` 指定一段 16kHz、16 位、单声道的 WAV。只测一个模型用 `LIVE_MODEL=模型 ID`。百炼限流每分钟 10 次连接，几种模式分开跑，连着跑会被限流。调试联调脚本本身时，可以用 `LIVE_ENDPOINT` 连本地的模拟服务。

开发用的环境变量，**只在未打包运行时生效**，打包后的应用会忽略：

| 变量                         | 作用                                                                                |
| ---------------------------- | ----------------------------------------------------------------------------------- |
| `LIVE_INTERPRETER_USER_DATA` | 换一个数据目录，不碰日常设置                                                        |
| `LIVE_INTERPRETER_ENDPOINT`  | 把服务地址换成别的 WebSocket 地址（不含 `?model=`），声音复刻接口也跟着换到同一主机 |

## 结构

```
src/
  shared/            各进程共用的类型、语种表、模型和协议、段落合并
  main/
    index.ts         IPC、退出和睡眠处理、全局快捷键、主题
    windows.ts       引擎、看板、设置、记录四个窗口
    state.ts         运行状态和翻译记录，变化时合并成一次广播
    translator.ts    一条通道 = 一个到百炼的 WebSocket 会话：按模型的协议握手和解析、断线重连、原文译文配成段落
    voice.ts         声音复刻接口
    event-batcher.ts 字幕事件 50ms 合并一次再发给窗口
    settings.ts      设置读写，Key 只在变化时加密一次，写盘有防抖
  preload/           暴露给页面的 window.api，按窗口角色区分
  renderer/src/
    engine/          隐藏窗口里的音频引擎：采集、播放、防回授、按住说话
    overlay/         字幕看板
    records/         翻译记录
    settings/        设置窗口
    panel/           看板和记录共用的外观、拖动和缩放
    audio/           采集（重采样到 16kHz）、录音（原采样率 WAV）、播放
tests/               单元测试、端到端测试（含模拟服务和测试音频生成）、真实服务联调
```

### 性能上的取舍

服务端推送的字幕是当前这段的累计全文，不是增量：

- 主进程每 50ms 合并一次，同一段只把最新一版发给窗口。
- 字幕按段落存，文本没变就复用原对象，每段用 `memo` 包起来，流式更新时只有正在说的那段重渲染；每个方向最多留 500 段记录。
- 运行状态放在主进程，变化合并成一次广播；防回授、按住说话只在状态翻转时上报。
- 音频采集在 AudioWorklet 线程里完成降混、重采样和 PCM16 转换，每 100ms 一块，用 transfer 交给主线程；IPC 传二进制，只在主进程发 WebSocket 前转一次 base64。
- 调字幕样式时本窗口立刻生效，最多每 100ms 保存一次；平时保存设置不访问系统钥匙串。
